# JASCA 사용자 안내

JASCA에서 하는 일상 작업을 순서대로 설명합니다. 화면 왼쪽 메뉴는 **홈, 프로젝트, 취약점, 스캔하기**, 검토 항목(**예외, 예외 승인**(보안 담당만)**, 사내 Advisory, 보고서**), 시스템 항목(**관리**, 관리자·보안 담당만)입니다. 단축키는 `?`로 볼 수 있습니다(`/` 검색, `g h` 홈, `g p` 프로젝트, `g f` 취약점, `g s` 스캔하기).

## 로그인

회사 SSO(Keycloak) 버튼으로 로그인합니다. 일정 시간(기본 30분) 아무 요청이 없으면 로그아웃되고, 한 계정으로 동시에 접속할 수 있는 수에도 한도(기본 3)가 있습니다. 비밀번호 로그인(`/login?local=1`)은 설치 직후와 비상용 관리자 한 계정만 씁니다.

## 홈

볼 수 있는 모든 프로젝트의 요약입니다: **열린 결과**(심각도별), **최근 30일 추세**, **오래 열린 CRITICAL 결과**, **14일 안에 만료되는 예외**, **최근 스캔**, **새로 알려진 취약점**(최근 7일간 재평가나 사내 Advisory로 기존 대상에서 새로 찾은 결과).

## 프로젝트와 멤버

프로젝트는 하나의 서비스나 팀의 검사 대상(이미지, 저장소, 앱)을 묶는 단위입니다.

1. **프로젝트 → 새 프로젝트**에서 이름과 키를 입력합니다. 키는 영문 소문자, 숫자, 하이픈으로 2~40자이며 URL과 CI 업로드 주소에 쓰이고 나중에 바꿀 수 없다고 생각하고 정하세요. 만든 사람이 소유자가 됩니다.
2. 프로젝트 화면의 탭은 **결과, 대상, 스캔 기록, 예외, 설정**입니다. **설정**은 일반, 멤버, CI 연동, API 토큰, MCP 연동, 정책, 알림, 삭제로 나뉘며 소유자만 바꿀 수 있습니다.
3. **설정 → 멤버**에서 누구에게 어떤 권한을 줄지 정합니다.

| 프로젝트 역할 | 할 수 있는 일 |
|---|---|
| 소유자 | 설정, 멤버, 토큰, 정책, 알림, 삭제 |
| 멤버 | 업로드, 서버 스캔, 예외 요청, AI 보고서 만들기 |
| 보기 전용 | 조회만 |

멤버는 **사용자**나 **Keycloak 그룹·부서 경로**로 지정합니다. 부서/그룹은 하위 경로 사람까지 포함합니다(예: `/AI실`로 지정하면 `/AI실/보안팀` 사람도 포함). 소유자가 한 명(또는 한 그룹) 이상 있어야 저장됩니다. 시스템 관리자는 모든 프로젝트의 소유자이고, 보안 담당은 모든 프로젝트를 읽을 수 있습니다. 보이지 않는 프로젝트는 "없는 프로젝트"처럼 보입니다.

## 스캔 결과 올리기

### CI에서 올리기 (권장)

1. 프로젝트 **설정 → API 토큰 → 토큰 만들기**: 이름, 권한(`upload`는 업로드, `read`는 읽기), 만료일(내일부터 최대 1년)을 정합니다. `jsc_`로 시작하는 토큰은 **만든 직후 한 번만** 보입니다. CI 비밀 변수 `JASCA_TOKEN`에 넣으세요. 토큰은 만든 프로젝트에서만 쓸 수 있습니다. 유출되면 같은 화면에서 폐기합니다.
2. **설정 → CI 연동**에서 대상 이름, 종류, 스캐너, gzip 여부를 고르면 복사용 명령이 만들어집니다. 예:

```sh
trivy image --format json --scanners vuln -o trivy.json "$IMAGE:$TAG"
curl -fsS -X POST -H "Authorization: Bearer $JASCA_TOKEN" --data-binary @trivy.json \
  "https://jasca.example.internal/api/v1/projects/<키>/scans?target=<대상 이름>&kind=image&ref=$TAG&scanners=vuln" | tee jasca.json
grep -q '"passed":true' jasca.json
```

   - `kind`: `image`, `repo`, `fs`, `sbom`. `ref`는 태그나 커밋 값입니다. 업로드 크기 한도는 기본 50MB이고, 큰 보고서는 `Content-Encoding: gzip`으로 보냅니다.
   - 올릴 수 있는 형식: Trivy JSON, SARIF, Harbor 취약점 보고서, CycloneDX JSON(SBOM). 형식은 자동으로 알아봅니다.
   - CycloneDX SBOM은 올리는 즉시 서버의 Trivy DB로 평가해 취약점을 채웁니다. 서버에 Trivy DB가 아직 없으면 패키지 목록만 저장되고 정책 판정은 **실패**("Trivy DB가 없어 평가하지 못했습니다")로 나옵니다.
   - 응답의 `policy.passed`가 `false`이면 정책 실패입니다. 위 `grep` 때문에 CI 작업이 종료 코드 1로 끝납니다.
   - 같은 보고서를 10분 안에 같은 대상에 다시 올리면 새 스캔을 만들지 않고 기존 스캔을 돌려줍니다(재시도 안전).
   - **스캐너 표시(`scanners`)**: 이 보고서가 그 종류를 끝까지 검사했다는 뜻이며, 같은 대상에서 이번 보고서에 없는 열린 결과를 자동으로 해결됨으로 바꾸는 근거가 됩니다. 실제로 돌린 스캐너만 적으세요.

### 서버에서 스캔 (파일 업로드)

**스캔하기 → 파일 올려서 검사**: 파일을 올리고, 결과를 저장할 프로젝트를 고른 뒤 **스캔 시작**을 누릅니다.

1. **검사할 파일**을 끌어다 놓거나 눌러서 고릅니다. 파일 종류(소스 코드·패키지 / 컨테이너 이미지)는 파일 내용을 보고 자동으로 고르고, 다르면 바꿀 수 있습니다.
   - **소스 코드·패키지**: 프로젝트 폴더를 압축한 `zip`, `tar`, `tar.gz`/`tgz`. 패키지 잠금 파일(`package-lock.json`, `go.mod`, `pom.xml`, `requirements.txt` 등)과 그 안의 JAR/WAR/EAR 파일을 검사합니다.
   - **컨테이너 이미지**: `docker save`나 `podman save`로 만든 이미지 tar. 이미지 tar를 소스 코드로 올리거나 압축 파일 안에 넣어 올리면 검사하지 않고, 어떻게 다시 올릴지 알려 주며 실패로 끝납니다.
2. **프로젝트**를 고릅니다. 아직 없으면 목록의 **+ 새 프로젝트 만들기**를 골라 이름과 키만 적으면 스캔을 시작할 때 함께 만들어집니다(만든 사람이 소유자). 마지막에 쓴 프로젝트는 다음에 미리 선택됩니다.
3. **대상 이름**은 파일 이름으로 채워집니다. 같은 이름으로 다시 스캔하면 이전 스캔과 비교해 새로 생긴 것과 사라진 것을 보여 줍니다.
4. 올리기 → 검사 → 결과 순서로 진행 상황이 보이고, 끝나면 심각도별 건수, 검사한 패키지 수, 정책 통과/실패가 같은 화면에 나옵니다. **결과 자세히 보기**로 스캔 상세로 이동합니다.
   - **검사하지 못한 것은 결과에 경고로 나옵니다.** Java DB가 없어 건너뛴 JAR/WAR/EAR 파일(개수 표시), 그리고 검사할 수 있는 패키지나 설정 파일을 하나도 찾지 못한 경우입니다. 뒤의 경우는 "결과 없음"이 아니므로 정책도 통과로 판정하지 않습니다(사유: 검사한 패키지나 설정 파일이 없음). CI에서 올린 보고서에는 이 판정을 적용하지 않습니다.

- 업로드 상한은 기본 2GiB입니다(관리자가 조정). 상한을 넘는 파일과 빈 파일은 고를 때 바로 거부됩니다. 압축 안의 절대 경로, `..`, 밖을 가리키는 링크는 거부됩니다.
- 스캔은 큐에 들어가 한 번에 한 건씩 처리됩니다(제한 시간 기본 15분). 진행은 스캔 상세 화면에서 보고, 요청한 사람, 프로젝트 소유자, 관리자는 **스캔 취소**를 할 수 있습니다. 끝나면 "정책 통과/실패"가 표시됩니다.
- 서버 스캔은 Trivy DB를 관리자가 올려 둔 뒤에만 동작합니다. 그 전에는 스캔 화면에 안내가 나오고 **스캔 시작**이 꺼져 있으며, API(`POST /projects/{key}/scan-jobs`)는 파일을 받지 않고 409로 답합니다. 레지스트리에서 이미지를 끌어오는 기능은 없습니다(Harbor 연동이 그 역할).

### Harbor

Harbor에서 스캔이 끝나면 자동으로 들어옵니다(관리자가 연결). 보고서만 받아 오므로 Harbor 대상은 재평가와 사내 Advisory 매칭 대상이 아닙니다(**대상** 탭에 "재평가 제외"로 표시). 매핑이 없는 이미지는 관리자가 프로젝트를 지정해야 합니다.

## 결과 읽기

**취약점** 메뉴(전체)나 프로젝트의 **결과** 탭에서 봅니다. 하나의 결과는 "대상 + 취약점(또는 설정 오류, 비밀값, 코드 분석 규칙) + 패키지/위치"로 구분되고, 스캔을 거듭해도 같은 결과로 이어집니다.

- **상태**: 열림, 해결됨(이후 스캔에서 사라짐), 위험 수용, 오탐. 해결됨 결과가 다시 나타나면 열림으로 돌아가고 재발로 표시됩니다. 위험 수용과 오탐은 예외 기간 동안 유지됩니다.
- **자동 해결 범위**: 같은 대상, 같은 결과 종류·도구의 **완전한** 새 스캔에 없는 열린 결과만 해결됩니다. 다른 대상이나 다른 도구의 스캔은 영향을 주지 않습니다.
- **순서**: 목록은 심각도가 높은 것(CRITICAL)부터, 같은 심각도 안에서는 최근에 발견된 것부터 나옵니다. 심각도는 CRITICAL, HIGH, MEDIUM, LOW, UNKNOWN으로 표시합니다.
- **필터**: 검색어(CVE, 패키지, 제목), 심각도, 상태(기본은 열린 결과만), 프로젝트, 대상, 종류(취약점, 설정 오류, 비밀값, 코드 분석), 출처(스캔, 재평가, 사내 Advisory), 조치 가능(조치 버전 있음). 필터는 주소에 남아 그대로 공유할 수 있습니다.
- **CSV 내려받기**: 현재 필터 결과를 CSV로 받습니다(엑셀 수식으로 해석되지 않게 처리됩니다).
- 행을 누르면 **세부 정보**가 열립니다: 맨 위에 무엇을 하면 되는지 한 문장(**할 일**), 그 아래 패키지, 설치 버전, 조치 버전, 경로·위치(`파일:줄`), 처음 발견·마지막 확인, 예외 상태, **취약점 상세**로 이동하는 링크. 심각도는 결과마다 저장되므로 배포판이 매긴 값이 그대로 보입니다.
- **취약점 상세**(CVE): 설명, CVSS, 참고 자료, 내가 볼 수 있는 영향받는 프로젝트·대상. 이 취약점이 아직 어떤 스캔에도 없으면 "카탈로그에 없는 취약점"으로 나옵니다.
- **스캔 상세**(프로젝트 → 스캔 기록 → 스캔 선택): 요약, 정책 통과/실패와 사유, 이전 스캔 대비 새로 발견·사라짐·그대로(같은 대상·형식의 이전 스캔이 없으면 이 스캔의 결과 목록만), 원본 보고서 내려받기(`scan-번호.json`, 보존 기간이 지나면 삭제됨. 서버 스캔의 보고서는 대상 이름이 `ArtifactName`이고, 소스 스캔이면 잠금 파일과 Java 파일의 결과가 한 파일에 들어 있습니다). 요약의 건수는 스캔이 끝났을 때 그 대상에 열려 있던 결과 전체라서, 같은 대상의 다른 스캔에서 찾은 것도 들어갑니다.

## 패키지 찾기

새 취약점이 발표된 날 "이 패키지를 어디에서, 어떤 버전으로 쓰고 있지?"에 답하는 화면입니다. 스캔할 때 저장해 둔 패키지 목록에서 찾으므로 취약점 DB에 아직 없는 취약점이어도 바로 찾을 수 있습니다.

- **패키지 찾기** 메뉴에서 패키지 이름을 2자 이상 입력하고 Enter를 누릅니다. 이름의 일부만 써도 되고 대소문자는 가리지 않습니다(예: `log4j-core`).
- **버전 조건**(선택): `<2.17.1`, `>=2.0 <2.17.1`처럼 범위를 쓰거나 `2.14.1`처럼 버전만 써서 정확히 그 버전을 찾습니다. 쓰는 법은 사내 Advisory의 영향 범위와 같습니다. 비워 두면 모든 버전을 찾습니다.
- 패키지 종류(maven, npm, debian 등)와 프로젝트로 좁힐 수 있습니다. 찾은 조건은 주소에 남아 그대로 공유할 수 있습니다.
- **찾는 범위**: 내가 볼 수 있는 프로젝트의 대상마다 **패키지 목록이 있는 가장 최근 스캔**을 봅니다. SARIF나 비밀값 결과만 올린 대상처럼 패키지 목록이 없는 대상은 찾을 수 없고, 화면에 "대상 N개는 패키지 목록이 없어 찾지 못합니다"로 나옵니다. 그런 대상은 이 화면에 안 나와도 그 패키지를 쓰고 있을 수 있습니다.
- **결과 표**: 패키지 · 종류, 버전, 프로젝트 · 대상, 위치(파일 경로, 여러 곳이면 "외 N곳"), 열린 취약점, 기준 스캔(그 패키지 목록이 나온 스캔의 날짜. 누르면 스캔 상세). 한 행은 한 대상에 있는 패키지 한 버전이고, 같은 프로젝트의 행이 모여 나옵니다.
- **열린 취약점**: 그 대상에서 같은 패키지·버전으로 열려 있는 결과 수와 그중 가장 높은 심각도입니다. 누르면 그 프로젝트의 결과 목록이 그 패키지와 대상으로 걸러져 열립니다. "없음"은 알려진 취약점이 아직 없다는 뜻이지 안전하다는 뜻이 아닙니다.
- **버전을 비교하지 못함**: 버전 표기가 달라 조건에 맞는지 판단할 수 없는 패키지는 빼지 않고 표 아래에 따로 보여 줍니다. 영향이 있는지 직접 확인하세요.
- 결과는 1,000건까지 보여 줍니다. 넘으면 안내가 나오니 이름을 더 길게 쓰거나 조건을 좁히세요. **CSV 내려받기**는 화면과 같은 행을 받습니다.
- 보안 담당에게는 **사내 Advisory로 등록** 버튼이 나옵니다. 찾은 패키지(10종까지)와 버전 조건이 채워진 새 Advisory 화면이 열리고, 내용을 확인해 저장하면 해당 패키지가 결과로 등록되어 정책과 알림에 반영됩니다.

## 예외 (위험 수용, 오탐)

고치지 않고 두거나 오탐으로 처리해야 하는 결과는 예외로 요청합니다.

1. **요청**: 결과 목록에서 하나 이상 고르거나 세부 정보에서 **예외 요청**을 누릅니다. 처리 방식(위험 수용 또는 오탐), 사유(승인자가 판단할 근거, 5자 이상), 만료일(내일부터 최대 1년)을 입력합니다. 열린 결과만 요청할 수 있고, 그 프로젝트의 멤버 이상이어야 합니다(보기 전용에게는 선택 칸과 버튼이 나오지 않습니다). 한 번에 한 프로젝트의 결과 최대 200건까지 요청합니다.
2. **승인**: 보안 담당이나 관리자가 **예외 승인** 화면(내 결정을 기다리는 요청만 모은 목록)에서 요청자와 요청일, 사유를 보고 승인하거나 반려합니다(메모는 요청자에게 보입니다). **본인이 요청한 예외는 직접 승인하거나 반려할 수 없습니다(두 버튼이 잠겨 있습니다).** 승인되면 해당 결과의 상태가 위험 수용 또는 오탐으로 바뀌고 정책 판정에서도 제외됩니다.
3. **만료**: 만료 7일 전에 알림이 가고, 만료일이 지나면 결과가 자동으로 열림으로 돌아옵니다(알림 포함). 승인 대기 중에 만료되면 요청도 만료됩니다.
4. **철회와 취소**: 대기 중인 요청은 요청자가 철회하고, 승인된 예외는 보안 담당이 **취소**해 결과를 다시 엽니다.
5. **예외** 메뉴에서 내 요청과 프로젝트별 예외 목록을 봅니다. 목록은 취약점 · 범위(누르면 취약점 상세. 그 아래 범위와 프로젝트, 결과 하나에 대한 예외는 패키지·심각도·대상도 표시), 처리 · 사유(결정 메모가 있으면 그 아래), 요청자 · 요청일, 상태 · 만료 순서이고 프로젝트의 **예외** 탭도 같습니다(프로젝트 이름만 빠짐). 만료 시각이 지난 예외는 바로 "만료됨"으로 보입니다.

예외 요청 창에서 범위를 고릅니다. **결과**(고른 결과만), **프로젝트 전체**(이 프로젝트의 같은 취약점 ID 전체), **전사**(모든 프로젝트, 보안 담당만)입니다. 프로젝트 전체와 전사 범위는 같은 취약점 ID 하나를 고른 경우에만 보입니다. 프로젝트 멤버가 아닌 보안 담당에게는 전사 범위만 나옵니다. 같은 대상에 승인 대기 중인 요청이 있으면 새 요청은 거부됩니다.

## 사내 Advisory

공개 DB에 없는 사내 취약점(자체 개발 라이브러리, 내부에서 알게 된 문제)을 직접 등록하는 기능입니다. 목록은 누구나 볼 수 있고 등록·수정·삭제는 보안 담당만 합니다.

1. **사내 Advisory → 새 Advisory**: ID(대문자 시작, 대문자·숫자·하이픈 3~41자, 예 `INT-2026-001`), 제목, 심각도, 설명, 참고 링크를 입력하고 **영향 범위**를 행으로 추가합니다. 각 행은 패키지 종류(npm, pip, maven, debian 등), 패키지, 영향 범위, 조치 버전입니다.
   - 영향 범위 예: `<1.4.2`, `>=1.0 <1.2.5`, `>=1.0, <1.2.5 || >=2.0, <2.0.3`. 공백이나 쉼표는 AND, `||`는 OR입니다.
   - 패키지 종류는 목록에서 고르거나 직접 입력합니다. 모르는 종류는 일반 비교로 처리되고 경고가 표시됩니다.
2. **영향 미리보기**로 어떤 프로젝트·대상이 걸리는지 저장 전에 확인합니다(미리보기는 아무것도 바꾸지 않습니다).
3. 저장하면 **기존 모든 최신 스캔의 패키지 목록과 즉시 대조**해 결과가 만들어지고(출처 "사내 Advisory"), 이후 올라오는 스캔에도 자동으로 적용됩니다. 수정하거나 "사용 중"을 끄거나 삭제하면 그로 인한 결과도 정리됩니다.
4. **CSV 가져오기**: 헤더 `id,title,severity,ecosystem,package,range,fixed,description,refs`(필수는 `id,title,severity,ecosystem,package,range`). 같은 `id`가 있으면 덮어쓰고, `refs`는 공백으로 구분합니다. **샘플 내려받기**로 양식을 받으세요. 한 행은 하나의 영향 패키지입니다.

## 보고서와 AI

- **보고서 → 프로젝트 선택**: 인쇄할 수 있는 **프로젝트 현황 보고서**(요약, 정책, 대상별 현황, 주요 취약점, 예외)가 열립니다. 주요 취약점에는 CRITICAL·HIGH만 싣고, 나머지 등급은 건수만 적습니다. **인쇄 / PDF** 버튼으로 브라우저의 PDF 저장을 씁니다.
- **AI 보고서 만들기**: 관리자가 AI를 켜 두었을 때만 보입니다(꺼져 있으면 AI 버튼과 기록이 나오지 않습니다). 같은 화면에서 위험 요약, 우선순위, 조치 계획을 사내 LLM이 한국어로 작성합니다. 백그라운드에서 만들어지고(대기 중, 작성 중) 끝나면 **AI 보고서 기록**에 쌓입니다. 멤버 이상이 만들 수 있고 보기 전용도 기록은 볼 수 있습니다.
- **취약점 상세 → 내 프로젝트 기준 안내 받기**: 이 취약점의 요약과, 내가 볼 수 있는 프로젝트의 패키지·버전에 맞춘 조치 순서를 만듭니다. 일반 설명은 취약점별로 저장되고 "내 프로젝트" 부분은 요청할 때마다 내 권한 범위로 새로 만듭니다.
- AI는 사내 LLM만 사용하고 결과를 자동으로 반영하지 않습니다. 내용은 사람이 확인하세요.

## MCP로 조회하기

AI 코딩·보안 에이전트(MCP 클라이언트)를 JASCA에 연결하면 에이전트가 프로젝트의 결과, 대상, 스캔 기록, 예외, 패키지 목록을 직접 조회합니다. 예를 들어 에이전트에게 "이 프로젝트의 열린 CRITICAL 취약점과 조치 버전을 정리해 줘"라고 시킬 수 있습니다. **조회만** 할 수 있고, 토큰이 속한 **프로젝트 하나만** 보입니다.

1. 프로젝트 **설정 → API 토큰**에서 **읽기**(`read`) 권한 토큰을 만듭니다(소유자). 업로드 권한만 있는 CI 토큰으로는 연결되지 않습니다.
2. **설정 → MCP 연동**에서 주소(`https://<접속 주소>/mcp`)나 설정 예시를 복사해 MCP 클라이언트 설정에 넣고 `<토큰>`을 토큰 값으로 바꿉니다.

```json
{
  "mcpServers": {
    "jasca-<키>": {
      "type": "http",
      "url": "https://jasca.example.internal/mcp",
      "headers": { "Authorization": "Bearer <토큰>" }
    }
  }
}
```

| 도구 | 에이전트가 할 수 있는 일 |
|---|---|
| `project_summary` | 프로젝트 요약: 심각도별 열린 결과 수, 대상 수, 마지막 스캔 시각, 정책 기준 |
| `list_findings` | 결과 목록. 심각도, 상태, 종류, 대상, 검색어, 조치 버전 유무로 거릅니다 |
| `get_finding` | 결과 한 건의 상세: 위치, 설치·조치 버전, 예외 상태 |
| `get_vulnerability` | 취약점(CVE) 설명, CVSS, 참고 링크와 이 프로젝트에서 영향받는 대상 |
| `list_targets` | 대상 목록: 종류, 마지막 스캔 시각, 심각도별 열린 결과 수 |
| `list_scans` | 최근 스캔: 상태, 결과 수, 정책 통과·실패와 그 이유 |
| `get_scan` | 스캔 한 건과 직전 스캔 대비 새 결과·해결·그대로인 결과 수 |
| `list_exceptions` | 예외 목록: 범위, 처리 방식, 상태, 요청자, 만료일 |
| `search_packages` | 패키지 찾기: 이름과 버전 조건으로 대상별 최신 패키지 목록에서 찾고, 패키지별 열린 취약점 수를 알려 줍니다 |

- 전송 방식은 Streamable HTTP입니다(요청마다 JSON으로 한 번 응답, SSE와 OAuth 로그인은 쓰지 않음). MCP 규격 2026-07-28과 그 이전의 2025-11-25, 2025-06-18, 2025-03-26 클라이언트를 모두 받습니다.
- 여러 프로젝트를 보려면 프로젝트마다 토큰을 만들어 따로 연결합니다. 다른 프로젝트의 결과나 스캔 번호를 물으면 "없음"으로 답합니다.
- 에이전트의 조회는 화면 조회와 마찬가지로 감사 로그에 남지 않고, 토큰 목록의 **마지막 사용**에 나타납니다. 토큰 하나는 1분에 300번까지 요청할 수 있습니다.
- 취약점 설명과 제목은 스캐너 보고서에서 온 글입니다. 에이전트가 그 글을 지시로 받아들이지 않도록 에이전트 쪽의 도구 승인 설정을 켜 두세요.

## 알림 받기

프로젝트 소유자가 **설정 → 알림**에서 관리자가 등록한 채널(Mattermost, 이메일) 중 받을 곳과 이벤트(새 CRITICAL/HIGH, 정책 실패, 스캔 실패, 예외 요청·승인·반려·만료 임박·만료, 새로 알려진 취약점)를 고릅니다.

## 자주 하는 질문

- **프로젝트가 보이지 않아요**: 멤버로 지정되지 않았습니다. 소유자에게 사용자나 소속 부서·그룹으로 추가해 달라고 하세요. 부서·그룹은 Keycloak 동기화 이후에 반영됩니다.
- **CI에서 401이 나와요**: 토큰이 만료·폐기됐거나 다른 프로젝트의 토큰이거나 `upload` 권한이 없습니다.
- **MCP 클라이언트가 연결되지 않아요**: 401이거나 클라이언트가 OAuth 로그인·"Dynamic Client Registration" 오류를 말하면 토큰이 틀렸거나 만료·폐기된 것입니다. 403이면 `read` 권한이 없는 토큰입니다. 주소는 `/mcp`로 끝나야 합니다.
- **결과가 해결됨으로 바뀌었어요**: 같은 대상의 완전한 새 스캔에서 사라졌기 때문입니다. 다시 나타나면 열림으로 돌아옵니다.
- **정책이 실패해요**: 스캔 상세의 정책 사유를 보고, 고치거나 예외를 요청하세요. 승인된 예외는 세지 않습니다.
- **새로 알려진 취약점이 나왔어요**: 관리자가 Trivy DB를 갱신했거나 사내 Advisory가 등록되어 기존 대상을 다시 평가한 결과입니다. 스캔을 다시 하지 않아도 됩니다.
