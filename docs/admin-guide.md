# JASCA 관리자 안내

관리 화면은 왼쪽 메뉴 **관리**에 있습니다. 관리자(`admin`)는 모든 항목을, 보안 담당(`security`)은 **기본 정책**만 볼 수 있습니다. 설치와 Keycloak 설정 절차는 [DEPLOY-OFFLINE.md](../DEPLOY-OFFLINE.md)에 있습니다. 이 문서는 각 화면이 무엇이고 어떤 값을 넣는지 설명합니다.

모든 비밀값(Client Secret, API 키, 로봇 계정 Secret, 웹훅 URL, SMTP 비밀번호)은 저장한 뒤 화면에 다시 나오지 않고 "설정됨"만 보입니다. 비워 두고 저장하면 기존 값을 유지합니다. 모든 설정 변경은 **감사 로그**에 남습니다.

## 역할 요약

| 역할 | 할 수 있는 일 |
|---|---|
| 관리자 | 모든 프로젝트의 소유자 권한, 모든 관리 화면 |
| 보안 담당 | 모든 프로젝트 읽기, 예외 승인·반려, 사내 Advisory 관리, 기본 정책 수정 |
| 일반 사용자 | 프로젝트를 만들 수 있고(만든 사람이 소유자), 멤버로 지정된 프로젝트만 봄 |

시스템 역할은 **사용자·역할**에서 지정하거나 Keycloak 역할로 자동 지정합니다. 프로젝트 안의 역할(소유자, 멤버, 보기 전용)은 프로젝트 소유자가 정합니다.

## 사용자·역할

동기화되었거나 로그인한 사용자 목록입니다(이름·아이디·이메일, 계정 종류(SSO 또는 로컬), 부서, 역할, 마지막 로그인, 활성 여부). 검색 칸에서 이름, 아이디, 이메일, 부서로 찾습니다.

- **역할**: 일반 사용자, 보안 담당, 관리자 중에서 고르면 바꿀 사용자와 새 역할을 확인하는 창이 뜨고, 확인해야 저장됩니다. Keycloak 역할 매핑을 따르는 사용자("Keycloak 역할 따름")도 여기서 바꿀 수 있습니다. 바꾼 역할은 JASCA 안에서만 적용되고(Keycloak의 역할은 그대로), 그 뒤로는 로그인해도 Keycloak 역할로 되돌아가지 않습니다. 다시 Keycloak을 따르게 하려면 역할에서 **Keycloak 역할 따름**을 고릅니다. 역할은 그 사용자가 다음에 Keycloak으로 로그인할 때 다시 정해집니다(그때까지는 지금 역할 유지). 자기 자신의 관리자 권한을 내리거나 자기 계정을 비활성화할 수는 없습니다.
- 로컬 `admin`은 Keycloak에 문제가 생겼을 때 들어오는 비상용 계정이라, 다른 관리자도 비활성화하거나 역할을 바꿀 수 없습니다(화면에서 잠겨 있고 API도 거부합니다).
- 계정 비활성화는 다음 요청부터 적용됩니다.
- 부서는 읽기 전용입니다. Keycloak에서 바꾸세요. 그룹은 이 화면에 나오지 않습니다(프로젝트 **설정 → 멤버**에서 그룹 경로로 지정할 때 씁니다).
- 안전한 기본값: 관리자는 최소 인원으로, 평소 업무는 일반 사용자나 보안 담당으로 둡니다.

### MCP 키

같은 화면 아래의 **MCP 키** 표는 사용자들이 AI 에이전트 연결용으로 만든 개인 키 전체입니다(사용자, 키 이름과 앞 12자, 읽기 전용 여부, 마지막 사용, 만료). 키 값은 어디에도 저장되지 않아 관리자도 볼 수 없습니다. 위의 사용자 검색이 이 표에도 적용됩니다.

- 키는 **그 사용자의 지금 권한**으로 동작합니다. 역할을 내리면 다음 요청부터 도구가 줄고, 계정을 비활성화하면 그 사용자의 키가 모두 멈춥니다(다시 활성화하면 다시 동작합니다). Keycloak에서 지워진 사용자는 동기화 뒤 비활성화되므로 키도 함께 멈춥니다.
- **폐기**를 누르면 그 키로 연결한 에이전트가 바로 끊깁니다. 유출 신고를 받았을 때 씁니다. 발급과 폐기는 감사 로그에 남습니다("MCP 키 생성", "MCP 키 폐기").
- 키로 한 변경은 감사 로그에 그 사용자 이름으로 남고 행위자 옆에 **MCP** 표시가 붙습니다(마우스를 올리면 키 이름).
- 키는 계정당 20개, 만료는 최대 1년입니다. MCP 주소(`/mcp`)와 스캔 업로드 두 경로에서만 받아들이고, 그 밖의 API는 거부합니다.

### 관리자용 MCP 도구

관리자가 자기 MCP 키(사용자 메뉴 → **MCP 키**)로 에이전트를 연결하면 사용자 도구에 더해 운영 도구가 보입니다. "지금 상태 어때?", "어제 실패한 스캔 원인 찾아 줘", "Keycloak 로그인 오류 로그 보여 줘" 같은 질문에 에이전트가 직접 답합니다.

| 도구 | 하는 일 |
|---|---|
| `system_status` | 버전과 가동 시간, DB(버전, 크기, 연결 수), 데이터 볼륨 남은 공간, Trivy DB 설치 여부와 경과 일수, 스캔 대기·진행·실패 수, 마지막 재평가, Keycloak 동기화, 알림 전송, 승인 대기 예외, 전체 수치. `problems`에 조치가 필요한 것만 문장으로 나옵니다 |
| `get_server_logs` | 서버 로그에서 찾기(검색어, 최근 N분). 마지막 시작 이후 최근 2,000줄을 메모리에 둡니다. 그 이전 로그는 `kubectl logs`로 봅니다 |
| `list_all_scans` | 모든 프로젝트의 스캔(기본: 최근 72시간의 대기·진행·실패)과 오류 문구 |
| `list_notifications` | 알림 전송 내역(기본: 실패·대기)과 마지막 오류 |
| `list_users`, `update_user` | 사용자 목록과 역할 변경·비활성화(화면과 같은 제한: 자기 자신과 로컬 `admin`은 내릴 수 없음) |
| `list_mcp_keys`, `revoke_mcp_key` | 전체 사용자의 MCP 키와 폐기 |
| `get_settings` | 조치 기한, 보존 기간, 기본 정책, SSO, 동기화, Trivy 옵션, AI, SMTP, 알림 채널, Harbor 연결을 **비밀값 없이** 조회 |
| `run_keycloak_sync`, `start_recheck` | 지금 동기화, 재평가 시작 |
| `list_harbor_unmapped`, `assign_harbor_image` | 매핑되지 않은 Harbor 이미지와 프로젝트 연결 |

- 설정 변경(SSO, SMTP, 알림 채널, AI, Harbor 연결, Trivy DB 올리기, 조치 기한, 보존 기간)은 MCP로 할 수 없습니다. 비밀값이 오가는 일은 화면에서만 합니다.
- 운영 도구는 키 주인이 **호출하는 순간에 관리자**여야 보입니다. 관리자에서 내려가면 같은 키로도 더는 쓸 수 없습니다.
- 조회만 맡길 에이전트에는 **읽기 전용** 키를 쓰세요. 읽기 전용 키는 `update_user`, `revoke_mcp_key` 같은 변경 도구를 쓰지 못합니다.
- 보안 담당의 키에는 `decide_exception`(예외 승인·반려)과 `create_advisory`(사내 Advisory 등록)가 더해집니다.

## SSO (Keycloak)

Keycloak 로그인 연결입니다.

| 항목 | 설명 |
|---|---|
| SSO 로그인 사용 | 끄면 로컬 계정으로만 로그인합니다. |
| Issuer URL | 예: `https://sso.example.internal/realms/<realm>`. 구형 Keycloak은 `/auth/realms/<realm>`. 토큰의 `issuer`와 글자 그대로 같아야 합니다. |
| Client ID / Client Secret | Keycloak 로그인 client의 값 |
| 관리자 역할 | 이 Keycloak 역할을 가진 사용자는 시스템 관리자가 됩니다. |
| 보안 담당 역할 | 이 역할을 가진 사용자는 보안 담당이 됩니다. |
| 사이트 주소 | 예: `https://jasca.example.internal`. 콜백 주소(`/api/v1/auth/sso/callback`), Harbor 웹훅 URL, 알림 링크의 기준입니다. 비우면 브라우저가 접속한 주소를 씁니다. |

안전한 기본값: 사이트 주소를 항상 입력하고, 역할 이름은 비워 두지 않습니다(비우면 그 역할로는 아무도 승격되지 않습니다). 설정을 잘못 저장해도 `/login?local=1`로 로컬 `admin`이 들어올 수 있습니다.

## Keycloak 동기화

서비스 계정으로 Keycloak의 그룹, 사용자, 이메일, 부서를 주기적으로 가져옵니다. 프로젝트 멤버를 그룹이나 부서 단위로 지정하려면 필요합니다.

| 항목 | 설명 |
|---|---|
| 서비스 계정 Client ID / Secret | `view-users` 권한이 있는 서비스 계정 client |
| 동기화 주기(분) | 기본 15, 1~1440 |
| 부서 속성 이름 | 기본 `department`. 토큰 클레임과 사용자 속성 이름이 같아야 합니다. |
| 부서 정보를 읽지 않음 | 켜고 저장하면 저장된 모든 사용자의 부서가 지워지고 부서로 얻은 접근이 사라집니다. 켜 있는 동안은 로그인과 동기화가 부서를 저장하지 않습니다. |

- **지금 동기화** 버튼으로 바로 실행하고 결과(그룹 수, 사용자 수 또는 오류)를 봅니다. 마지막 실행 시각과 오류도 이 화면에 보입니다.
- **최근 SSO 로그인의 부서** 표: 최근 20건의 로그인에서 부서를 어디서 읽었는지(토큰 클레임, Admin API, 클레임 비어 있음, 못 찾음, 읽기 실패)를 보여 줍니다. 서버를 다시 시작하면 비워집니다. 첫 로그인에서 부서가 비면 먼저 이 표를 보세요.
- Keycloak에서 비활성화되거나 삭제된 사용자는 동기화 뒤 다음 요청부터 로그아웃(401)됩니다.
- 안전한 기본값: 사용자가 `department`를 스스로 고칠 수 없게 Keycloak을 설정한 뒤에 켭니다(부서가 접근 권한이 되기 때문입니다).

## 기본 정책

자체 정책을 저장하지 않은 프로젝트에 적용되는 정책입니다. 프로젝트 **설정 → 정책**과 같은 문장으로 정합니다("열린 결과 중 심각도 ○ 이상이 ○개를 넘으면 정책 실패"). 보안 담당도 수정할 수 있습니다.

| 항목 | 설명 |
|---|---|
| 기본 정책 사용 | 끄면 정책이 없는 프로젝트는 스캔을 판정하지 않습니다. 화면에는 '정책 사용 안 함'으로 나오고, CI 업로드 응답의 `policy.passed`는 `true`(`disabled: true`와 함께)입니다. |
| 최소 심각도 | 이 등급 이상만 셉니다(CRITICAL, HIGH, MEDIUM, LOW) |
| 허용 개수 | 이 개수를 **넘으면** 정책 실패. 0이면 하나라도 있으면 정책 실패 |
| 조치 버전이 있는 결과만 셉니다 | 조치 가능한 결과만 셉니다 |
| 이번 스캔에서 새로 나온 결과만 셉니다 | 이번 스캔에서 처음 나온 결과만 셉니다 |

저장하지 않았을 때의 값은 "사용, CRITICAL, 허용 0"입니다. 승인된 예외(위험 수용, 오탐)는 세지 않습니다. 정책을 판정하다 오류가 나면 실패로 처리합니다. 프로젝트 소유자는 프로젝트 **설정 → 정책**에서 자기 프로젝트의 기준을 따로 정할 수 있습니다.

### 조치 기한

같은 화면 아래의 **조치 기한**에서 열린 결과를 며칠 안에 조치해야 하는지 심각도별로 정합니다. 모든 프로젝트에 똑같이 적용되고(프로젝트별 설정은 없음) **관리자만** 보고 바꿀 수 있습니다.

| 항목 | 기본 | 설명 |
|---|---|---|
| 조치 기한 사용 | 켬 | 끄면 정책으로 정해진 기한이 모두 사라집니다. 사람이 결과 화면에서 직접 정한 기한은 남습니다. |
| CRITICAL / HIGH / MEDIUM / LOW | 7 / 30 / 90 / 180일 | 결과가 열림이 된 날부터의 일수(1~3650). **기한 없음**을 고르면 그 심각도에는 기한을 두지 않습니다. UNKNOWN에는 기한이 없습니다. |

- 기한은 결과가 **열림이 된 날**(처음 발견, 스캔에서 다시 나타남, 예외 만료·취소)부터 셉니다.
- **저장하면 지금 열려 있는 결과의 기한을 새 기준으로 다시 계산합니다**(저장 전에 확인 창이 뜨고, 바뀐 건수를 알려 줍니다). 직접 정한 기한은 바꾸지 않습니다. 기한이 바뀐 결과는 임박·지남 알림을 다시 받을 수 있습니다.
- 기한이 지난 결과는 홈·프로젝트·목록·보고서에 **기한 지남**으로 나오고, 프로젝트가 구독했으면 알림이 갑니다(**알림 채널** 참고). 정책 판정(CI 통과·실패)에는 영향을 주지 않습니다.
- **v1.1.0으로 업그레이드한 설치**: 이미 열려 있던 결과의 기한은 업그레이드한 시점부터 셉니다. 올리자마자 기한이 지난 결과가 생기지 않고, 설정을 저장하지 않아도 기본 일수로 기한이 붙습니다.
- 담당자와 기한을 누가 바꿨는지는 감사 로그에 "결과 담당자 지정", "결과 기한 변경", "조치 기한 정책 변경"으로 남습니다.

## Trivy DB

서버 스캔과 재평가에 쓰는 DB를 올리고, 서버가 Trivy를 돌릴 때 쓸 옵션을 정합니다. 화면 오른쪽 위에 Trivy 버전이 보입니다.

- **취약점 DB(`db.tar.gz`)와 Java DB(`javadb.tar.gz`)**: 칸이 따로 있고, 칸마다 설치 여부(설치됨/설치 안 됨), 생성 시각, 올리기 버튼과 진행률이 있습니다. 취약점 DB 칸에는 다음 갱신 예정도 보이며, 거기서 7일 넘게 지나면 경고가 보입니다.
  - 파일 종류는 내용으로 구분합니다. 칸을 잘못 골라도 맞는 DB에 적용하고, 무엇을 적용했는지 알림과 "방금 적용됨" 표시로 알려 줍니다. 올바르지 않은 파일은 거부되고 기존 DB가 유지됩니다.
  - 취약점 DB를 적용하면 **재평가**가 자동으로 시작합니다. Java DB는 재평가를 시작하지 않습니다(저장된 패키지 목록은 달라지지 않으므로). 다음 서버 스캔부터 적용되니, Java 파일이 든 대상은 다시 스캔하세요.
  - Java DB는 서버 스캔이 JAR/WAR/EAR 파일을 검사할 때 씁니다. 컨테이너 이미지와 압축 파일(소스 코드·패키지) 모두 해당합니다. 압축 파일 스캔은 Trivy를 두 번 실행합니다: 잠금 파일을 읽는 `trivy fs`(JAR는 열지 않음), 그리고 Java 파일만 모아 읽는 `trivy rootfs`. 두 결과는 한 스캔, 한 원본 보고서로 저장되고 스캔 옵션과 제한 시간도 두 실행에 함께 적용됩니다.
  - Java DB가 없으면 서버 스캔은 JAR/WAR/EAR 파일만 건너뛰고 나머지를 검사하며, **스캔 결과에 검사하지 못한 Java 파일이 있다고 경고로 표시합니다**(압축 파일 스캔은 파일 개수까지). Trivy는 Java DB 없이 JAR를 만나면 스캔 전체를 실패시키므로, 이미지는 그 실패를 본 뒤 Java 파일을 빼고 한 번 더 실행합니다. `pom.xml` 같은 잠금 파일과 CycloneDX의 Maven 패키지 평가에는 Java DB가 필요 없습니다. Java DB를 취약점 DB보다 먼저 올려도 됩니다.
  - 취약점 DB가 없으면 서버 스캔을 받지 않습니다(스캔 화면에 안내, API는 409). 홈의 첫 화면도 관리자에게 DB 올리기를 먼저 안내합니다.
  - 인터넷 PC에서 받는 방법(`oras pull ghcr.io/aquasecurity/trivy-db:2`, `trivy-java-db:1`)은 화면의 "인터넷 PC에서 파일 받는 방법"을 펼치면 나옵니다.
- **스캔 옵션**: 서버가 Trivy를 직접 실행하는 서버 스캔, CycloneDX(SBOM) 업로드 평가, 재평가에 똑같이 적용됩니다. CI나 Harbor에서 올라온 보고서는 이미 검사가 끝난 결과라 바뀌지 않습니다. 한 번에 저장하며 변경은 감사 로그(`trivy.settings`)에 남습니다.

  | 옵션 | 기본값 | 바꾸는 것 |
  |---|---|---|
  | 스캐너 | 취약점, 비밀값 | 취약점·비밀값·설정 오류 중 무엇을 찾을지(서버 스캔) |
  | 패키지 종류 | OS 패키지, 언어 라이브러리 | 한쪽만 볼 때 끕니다 |
  | 개발용 의존성도 검사 | 끔 | npm·yarn·gradle의 개발용 의존성 포함(압축 파일 스캔만) |
  | 결과에 넣을 심각도 | 전부 | 체크한 심각도(CRITICAL, HIGH, MEDIUM, LOW, UNKNOWN)만 결과에 넣음 |
  | 조치 버전이 없는 취약점 제외 | 끔 | 패치가 아직 없는 취약점을 뺌 |
  | 건너뛸 디렉터리 / 파일 | 없음 | glob 패턴, 한 줄에 하나(각 50개, 200자까지). 압축 파일·이미지 스캔만 |
  | 탐지 방식 | 정확하게 | "빠짐없이"는 더 많이 찾지만 오탐이 늘어남 |
  | 스캔 1건 제한 시간 | 비움(`JASCA_SCAN_TIMEOUT_MIN`, 기본 15분) | 1~240분. 넘기면 스캔을 중단하고 실패로 표시 |

  결과에서 제외하도록 바꾸면(심각도, 조치 버전 없음, 건너뛸 경로, 패키지 종류), 이미 열려 있던 항목 중 제외 대상은 그 대상의 다음 스캔에서 **해결됨**으로 바뀝니다(옵션을 되돌리면 다음 스캔에서 다시 열립니다). **스캐너를 끄는 것은 다릅니다**: 그 종류(예: 비밀값)는 아예 검사하지 않으므로, 이미 열려 있던 그 종류의 결과는 해결됨으로 바뀌지 않고 열린 채 남습니다. 감사나 보고 기준이 걸려 있으면 바꾸기 전에 확인하세요.
- 안전한 기본값: DB는 정기적으로(예: 매주) 올립니다. 올리기 전에 `sha256sum`으로 파일을 확인하세요. 스캔 옵션은 기본값이면 아무것도 제외하지 않습니다.

## 재평가

저장된 스캔의 패키지 목록을 최신 Trivy DB와 사내 Advisory로 다시 대조해 **새로 알려진 취약점**을 찾습니다. 스캔을 다시 돌릴 필요가 없습니다.

- DB를 올리면 자동으로 실행합니다. **지금 재평가**로 수동 실행도 됩니다(이미 실행 중이면 거부).
- 실행 기록 표에 사유, 상태, 진행(완료/전체 대상), 새로 찾은 결과 수, 시작·종료 시각, 오류가 보입니다. 서버를 다시 시작하면 이어서 진행합니다.
- 재평가는 결과를 **추가만** 하고 해결됨으로 바꾸지 않습니다. 새 결과는 "재평가"로 표시되고 알림(새로 알려진 취약점) 대상이 됩니다.
- 새 스캔이 들어오면 스캔이 우선합니다. Harbor 보고서 대상은 패키지 목록이 없어 제외됩니다.

## Harbor

Harbor 스캔 보고서를 웹훅으로 받습니다. 설정 절차는 [DEPLOY-OFFLINE.md](../DEPLOY-OFFLINE.md)의 "Harbor 웹훅 연동"을 보세요.

- **연결**: 이름, Harbor 주소, 로봇 계정, 로봇 계정 Secret. 만들 때 **웹훅 URL**과 **웹훅 Secret**이 한 번만 보입니다(Harbor 웹훅의 Auth Header에 넣습니다). **연결 시험**으로 접속을 확인합니다.
- **매핑**: Harbor 프로젝트 + 저장소 패턴(`web/*`, `*` = 전체) → JASCA 프로젝트. 더 구체적인 패턴이 먼저 적용됩니다.
- **매핑되지 않은 이미지**: 웹훅으로 받았지만 매핑이 없는 이미지입니다. 프로젝트를 고르면 연결하고 보고서를 가져옵니다.
- 안전한 기본값: 로봇 계정에는 해당 프로젝트의 읽기(pull) 권한만 줍니다. JASCA는 등록한 Harbor 주소로만 호출합니다.

## AI

사내 OpenAI 호환 LLM으로 취약점 조치 안내와 프로젝트 보고서를 만듭니다. 이 화면에 적은 주소 외에는 호출하지 않습니다.

| 항목 | 설명 |
|---|---|
| AI 기능 사용 | 켜야 사용자 화면에 AI 버튼과 안내가 나옵니다. 꺼져 있으면 "AI 안내는 관리자가 켜면 쓸 수 있습니다." 한 줄만 보입니다. |
| Base URL | 예: `http://llm.example.internal:8000/v1`. JASCA가 뒤에 `/chat/completions`를 붙여 호출합니다. |
| API 키 | 필요할 때만 |
| 모델 이름 | 서버가 받는 모델 이름 |
| 응답 대기 시간(초) | 1~600. 저장하지 않았을 때 기본 120 |
| 최대 입력 토큰 | 100~1,000,000. 저장하지 않았을 때 기본 12,000. 넘으면 취약점 목록을 줄여 보냅니다. |

- **연결 시험**으로 응답을 확인합니다.
- **프롬프트**: 취약점 조치 가이드, 프로젝트 보고서의 지시문을 고칠 수 있습니다. 비우면 내장 기본값을 씁니다(처음에는 비어 있고, 그대로 써도 됩니다). 바꾸려면 **기본 프롬프트 불러오기**로 채운 뒤 고치세요. 관리자만 고칠 수 있습니다.
- AI 입력은 서버가 DB에서 만들며 요청한 사용자가 볼 수 있는 프로젝트 데이터만 담습니다. 사용자가 올린 파일이나 URL은 보내지 않습니다.
- 추론 흔적(`</think>` 등)은 답에서 지웁니다. 응답이 느린 추론 모델이면 응답 대기 시간을 늘리고 Ingress 제한 시간도 확인하세요.

## 알림 채널

새 취약점, 정책 실패 같은 이벤트를 보낼 곳을 등록합니다. 프로젝트 소유자는 프로젝트 **설정 → 알림**에서 이 채널 중 받을 곳과 이벤트를 고릅니다.

- **채널**: 종류(Mattermost 또는 이메일), 이름, 사용 여부.
  - Mattermost: Incoming Webhook URL(URL에 토큰이 들어 있어 비밀값으로 다룹니다).
  - 이메일: 받는 사람(쉼표나 줄바꿈으로 구분). 발송은 아래 SMTP 설정을 씁니다.
- **메일 서버(SMTP)**: 호스트, 포트(기본 587), 암호화(STARTTLS, TLS, 사용 안 함), 사용자 이름, 비밀번호(인증이 필요 없으면 비움), 보내는 사람.
- **시험 발송**으로 확인합니다. 전송은 DB 대기열에 쌓이고 실패하면 1분, 5분, 30분 뒤에 다시 시도합니다(4번째 실패에서 중단). 요청마다 제한 시간이 있고 응답 본문은 화면에 돌려주지 않습니다.
- 이벤트: 새 CRITICAL/HIGH 취약점, 정책 실패, 스캔 실패, 예외 요청·승인·반려, 예외 만료 임박·만료, 새로 알려진 취약점, 조치 기한 임박(기한 3일 전)·조치 기한 지남. 조치 기한 알림은 한 시간마다 확인해 프로젝트와 이벤트마다 한 건으로 모아 보내고, 결과 하나의 기한 하나에 한 번만 보냅니다. 예:

  ```
  [결제 API] 조치 기한 지남 3건
  조치 기한이 지났는데 아직 열려 있는 결과입니다.
  CRITICAL 1건, HIGH 2건
  - CRITICAL CVE-2022-37434 (zlib) · 대상 alpine-app · 기한 2026-12-10 23:59 · 담당 이개발
  - HIGH CVE-2026-4800 (lodash) · 대상 web · 기한 2026-12-09 14:20 · 담당 미지정
  - HIGH DS-0002 · 대상 web · 기한 2026-12-09 14:20 · 담당 미지정

  https://jasca.example.internal/projects/pay-api?due=overdue&sort=due
  ```

- **메시지 모양**: 첫 줄은 `[프로젝트 이름] 무슨 일`, 이어서 사람이 알아야 할 2~5줄(누가, 어느 취약점·대상, 심각도, 사유, 만료 시각), 마지막에 해당 화면 링크입니다. 링크는 SSO 설정의 **사이트 주소**가 있을 때만 붙고, 시각은 `JASCA_TZ` 기준입니다. 예:

  ```
  [결제 API] 예외 요청
  요청: 이개발
  취약점: CVE-2022-37434 · zlib · CRITICAL (대상 alpine-app의 결과 1건)
  처리: 위험 수용
  사유: 내부망 전용 서비스로 해당 기능을 쓰지 않음
  만료: 2026-12-10 23:59

  https://jasca.example.internal/exceptions?id=17
  ```

  사유·이름·제목처럼 사용자가 쓴 글은 한 줄로 이어 붙이고(300자까지) 글자 그대로 보냅니다. Mattermost에서는 링크·멘션(`@channel`)·서식으로, 메일에서는 HTML로 해석되지 않습니다.

## 보존 기간

오래된 스캔의 **원본 보고서, 패키지 목록, 결과 연결**(그 스캔에 어떤 결과가 있었는지)을 지우는 기준입니다. 스캔 기록, 결과와 상태 이력, 취약점 정보는 지우지 않습니다.

| 항목 | 기본 | 설명 |
|---|---|---|
| 대상당 최근 개수 | 20 | 대상마다 최근 N개의 스캔은 항상 남깁니다. |
| 보존 일수 | 90 | 이 기간 안의 스캔은 개수와 상관없이 남깁니다. |

지우는 조건은 "최근 N개 밖이고 **그리고** 보존 일수보다 오래됨"입니다. 대상의 현재 인벤토리(패키지가 있는 가장 최근 스캔)는 재평가와 사내 Advisory 매칭에 쓰이므로 조건에 걸려도 패키지 목록을 남깁니다. 업로드할 때(그 대상만)와 하루에 한 번(전체) 정리합니다. 지워진 스캔은 상세 화면에서 "보존 기간이 지나 삭제됨"으로 보입니다. 데이터베이스 크기 잡는 법은 DEPLOY-OFFLINE.md의 "자원과 규모"를 보세요.

## 감사 로그

누가 언제 무엇을 바꿨는지 기록입니다. 최신순이며 지울 수 없습니다. 행위자, 동작(예: "Keycloak 동기화", "API 토큰 생성", "Trivy DB 올리기". 마우스를 올리면 `sync.run` 같은 코드가 보입니다), 프로젝트(키), 대상, IP, 상세("키: 값" 형태, 값은 화면에서 쓰는 한국어 이름)를 보여 주고 동작 목록이나 프로젝트로 거릅니다. 멤버 변경은 누가 추가·제거되었고 누구의 역할이 바뀌었는지 이름으로 남습니다(종류마다 20명까지, 나머지는 수만). 삭제된 프로젝트의 기록도 프로젝트 칸에 키가 남고, API에서는 `?project=<키>`로 찾을 수 있습니다. 프로젝트 소유자는 자기 프로젝트의 기록만 API(`GET /api/v1/audit`)로 볼 수 있습니다(웹 화면은 관리자용만 있습니다).

AI 에이전트의 MCP 조회(`/mcp`)는 다른 조회와 마찬가지로 기록하지 않습니다. 개인 MCP 키로 한 **변경**은 그 사용자의 이름으로 기록되고 행위자 옆에 **MCP** 표시가 붙습니다. 키와 토큰을 만들고 폐기한 기록은 남고, 쓰이는지는 **MCP 키** 화면과 프로젝트 **설정 → API 토큰**의 마지막 사용으로 봅니다.
